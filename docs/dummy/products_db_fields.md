# 상품 DB 필드 설계 (실습 전용)

> 대상: `docs/dummy/products/`의 가상 상품 10건. 상품명 · 가격 · 정책은 전부 가상이며 실제 상품 데이터에 섞지 않는다.
> 1단계는 엑셀(`products_db.xlsx`)로 정리하고, 최종적으로 **Supabase**에서 관리한다. 엑셀 헤더는 한글, DB 컬럼은 영문(DB 이름)을 쓴다.
> 엑셀 시트 하나가 Supabase 테이블 하나에 대응한다.

## 시트 1: 상품 (한 행 = 상품 1개)

| 필드명 | DB 이름 | 예시 (P-0113) | 비고 |
|---|---|---|---|
| 상품코드 | product_id | P-0113 | 기본키, 중복 불가 |
| 상품명 | product_name | 대구사과칩 | |
| 분류 | category | 가공식품 | 가안, 기준 결정 필요 |
| 원산지 | origin | 대구 팔공산 | 모르면 `미확인` (납작만두) |
| 원재료 | ingredients | 사과 100% | |
| 규격 | spec | 60g | 단위가 제각각이라 텍스트로 둠 |
| 판매가 | price | 4900 | 숫자만 (원, 쉼표 없음) |
| 판매기간 | sale_period | (빈칸) | 성주 참외만 `4~7월` |
| 상품설명 | description | 설탕·첨가물 없음 | |
| 알레르기_성분 | allergens | 없음 | 상품에 직접 들어 있는 성분 |
| 교차오염_주의 | cross_contact | 견과류 | 생산 라인을 함께 쓰는 성분 |

## 시트 2: 보관 (한 행 = 보관 조건 1개)

| 필드명 | DB 이름 | 예시 | 비고 |
|---|---|---|---|
| 상품코드 | product_id | P-0113 | 상품 시트의 상품코드 (외래키) |
| 시점 | stage | 개봉 후 | 개봉 전 / 개봉 후 / 수령 후 |
| 보관방식 | storage_type | 상온 | 상온 / 냉장 / 냉동 |
| 기간_일 | days | 7 | 숫자(일). 1개월 = 30일로 환산 |
| 비고 | note | 밀봉해 서늘한 곳 | 원문 표현 등 |

- 상품마다 해당하는 시점만 적는다. 생과일·채소는 `수령 후`, 가공품은 `개봉 전`·`개봉 후`.
- 기간이 여러 개면 행을 나눈다 (예: 꿀사과 냉장 21일 / 상온 7일 → 2행).

## 시트 3: 주의사항 (한 행 = 주의사항 1개)

| 필드명 | DB 이름 | 예시 | 비고 |
|---|---|---|---|
| 상품코드 | product_id | P-0113 | 상품 시트의 상품코드 (외래키) |
| 구분 | area | 보관 | 보관 / 조리 / 도구 / 섭취 |
| 유형 | level | 금지 | 금지 / 주의 / 권장 |
| 내용 | content | 냉장 보관 | |
| 이유 | reason | 습기를 먹어 눅눅해짐 | |

## 시트 4: 배송정책 (모든 상품 공통)

| 항목 | 값 |
|---|---|
| 무료배송_기준금액 | 30000 |
| 기본배송비 | 2500 |
| 당일배송_지역 | 수성구, 달서구 |
| 당일배송_마감시각 | 14:00 |

## 필드를 나눈 이유

기준: **이 칸으로 찾거나, 거르거나, 계산할 일이 있는가.**

1. **문장을 여러 칸으로 쪼갬**
   - 설명 → 규격 · 판매가 · 상품설명: 가격이 문장 속에 있으면 가격으로 거르거나 무료 배송까지 남은 금액을 계산할 수 없다.
   - 알레르기·원산지 → 원산지 · 원재료 · 알레르기_성분 · 교차오염_주의: "들어 있음"(납작만두의 밀)과 "라인 공유"(사과칩의 견과류)를 한 칸에 넣으면 잘못 안내할 수 있다.
2. **문서에 없는데 새로 만듦**
   - 상품코드: 이름은 바뀔 수 있지만 코드는 바뀌지 않으므로 기본키로 쓴다.
   - 분류: 운영에 필요하다.
   - 판매기간: 계절 상품을 걸러낼 때 필요하다.
3. **보관 · 주의사항을 별도 시트로 뺌 (1:N)**
   - 처음에는 개봉전/개봉후 보관기간, 보관_주의사항을 상품 시트의 열로 두었다. 그러나 개봉 후 기간은 6/10, 금지 사항은 5/10이 비어 있었고, 꿀사과처럼 기간이 둘인 상품은 한 칸에 억지로 넣어야 했다.
   - 상품마다 해당하는 것만 행으로 적으면 빈 칸이 생기지 않고, 기간을 숫자로 둘 수 있으며, "냉동 금지 상품"처럼 바로 거를 수 있다.
   - 섭취_주의사항(흑마늘 진액)도 주의사항 시트의 `섭취` 구분으로 합쳤다.
4. **배송 정보를 별도 시트로 뺌**
   - 10건이 모두 같다. 상품마다 반복하면 정책이 바뀔 때 10곳을 고쳐야 하고 빠뜨리면 데이터가 어긋난다(정규화).
5. **일부러 쪼개지 않음**
   - 규격: `2kg(7~9개)`, `70ml × 30포`처럼 단위가 달라 지금은 텍스트로 둔다.
6. **저장하지 않음**
   - 보관 · 주의사항 시트에 상품명을 다시 적지 않는다. DB에서는 상품코드로 상품 테이블과 join해서 꺼낸다.

## 빈 값 규칙

- `미확인`: 원래 있어야 하는데 원문에 정보가 없음 (납작만두 원산지, 대추칩 개봉 전 보관)
- `없음`: 확인했고 해당 사항이 없음 (알레르기 성분 없음 등)
- 빈칸: 해당 개념이 없음 (판매기간이 없는 상시 판매 상품 등)
